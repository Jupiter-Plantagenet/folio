# Evidence export browser vertical — bounded, fixture-backed

## Implemented

The original `evidence` screen now submits the reviewed asynchronous export command instead of downloading the POST's job acknowledgement as though it were evidence. It requests `audit-v1`, explicitly excludes originals, pins the current case version in body and If-Match, sends current CSRF and a UUID idempotency key, and displays the returned job.

Status is refreshed on reopening/reloading the screen and through **Refresh export status**. This is intentional manual refresh, not an export worker or scheduler. Queued/leased/exhausted/ready states are server state, never fabricated completion. The manifest/digest and its incomplete verification/release limits remain inspectable. Download is enabled only after ready, uses the derived same-origin authenticated artifact endpoint (never a returned external URL), and publishes the exact bytes only after length/SHA-256/ETag agreement. A successful status does not authorize a later download: that request goes to the server again. Authorization failures clear displayed artifact/ready authority. Navigation aborts in-flight requests and prevents a late local download.

Only command UUID, frozen positive safe-integer case revision and job UUID (or empty string before acknowledgement) are stored in tab-scoped sessionStorage, namespaced by username/workspace/case. Restoration requires exact scalar types, rejects arrays/coercion and reconstructs the three-field whitelist before subsequent writes; extra fields are not copied. No manifest, source bytes, original, CSRF or session credential is persisted by this component. Only a successful read returning absent (`null`) permits a fresh command. Read exceptions, malformed JSON and invalid records block creation and preserve storage; **Retry recovery read** rereads without automatically submitting. Persistent ambiguity requires operator reconciliation and an explicit disposition outside this UI, not clearing storage or generating a new key.

A lost enqueue response keeps the same command key/body/If-Match for explicit retry, including after reload or a changed displayed case version. An acknowledgement must contain a string job UUID. A successful acknowledgement restores job status without another POST on reopen. All HTTP rejections, including412/422, now retain the original command identity: a later rejection cannot establish that an earlier ambiguous attempt did not commit. POST409 identity conflict asks for reconciliation; POST503 instructs same-command replay; POST422 size-limit failures explain that unchanged retries cannot reduce size. GET409/503 retain status-specific guidance. There is no automatic discard/reset/new-export action or backend job-discovery route. The component retains one job reference per account/case/tab; job history/new-export-after-expiry is outside this vertical. Clearing browser storage or closing the tab loses recovery identity and is not a supported reconciliation procedure.

Download accumulation uses one262144-byte buffer and a streamed reader. A declared oversize length is rejected before reading; actual overflow cancels the reader before copying the overflowing chunk, hashing or local publication. Only accumulated bytes are hashed after EOF, then length/digest/ETag are checked. This bounds component accumulation, not browser/network chunk allocation or total browser RAM; the browser may deliver a larger chunk which is rejected without copying it. Leaving the component aborts its lifetime and suppresses late acknowledgement persistence, status callbacks and publication. The unchanged main screen keys the component by account/workspace/case.
