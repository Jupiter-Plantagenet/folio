# ADR-003 — source-linked receipt allocations and information resumption

Status: bounded local implementation; independent review required. Normative originals unchanged.

## Required inventory / source authority

- Original `../portfolio-engineering/documents-blueprint.md` §§1,3,4 (especially lines 104,109–113),6,7: independently identified receipt/line rows, no aliases/import double count, nonnegative exact decimals, USD/each validation, ordered/invoiced/available receipt bound, unchanged invoice face, derived retained balance, immutable version-linked operands, separate approval and sealed history.
- `contracts/documents-contracts.json`: DOC-case/source/provenance/decision/proposal, DOC-decide/correct/intake/approve; DOC-T-ARITH/PROVENANCE/INTAKE/FLOW/STALE/AUTH/STATES. Original 14-screen direction remains authoritative (import/document/reconciliation/decision/changes are this slice, not 14 full passes).
- Missing/conflicting supporting documents require in-app information request, appended real parsed sources or explicitly versioned human correction, revalidation and fresh review; hold/escalation/no-change never dispatch. Required receipt quantity cannot be invented by correction.

## Decision

Use immutable parsed receipt rows plus a versioned allocation manifest inside the existing immutable proposal payload/digest. Receipt business key is exact supplier + external receipt ID + line ID; repeated content or alternate format aliases merge support references, never quantities. Different operands under one key block as conflict. Missing receipt IDs/line IDs block multi-receipt authority (legacy single-receipt fixtures remain visible and are not retroactively rewritten). USD and each are the supported policy; explicit mismatches block. Receipt line IDs identify one purchase-order line; no cross-line tax aggregation policy is introduced.

Serialize allocation preparation using a workspace-specific PostgreSQL advisory transaction lock, then sum reservations from other non-superseded pending/approved proposals and all sealed/uncertain/applied history. Expired pending drafts release reservations; approved/unknown authority remains reserved conservatively. Cross-case receipt reuse cannot exceed supported quantity; same-target duplicate active proposals are denied. The case lock is acquired before this workspace lock consistently. No new mandatory shared runtime or destructive schema migration.

Receipt totals and allocation sums use Decimal (bounded scale/lexical inputs); independent tests use Fraction. Proposal embeds source ID/version/hash/span and exact allocated quantity. Allocation manifests are not rewritten on correction: old proposal financial payload/digest/attestation remains unchanged; the existing lifecycle state records supersession. Sealed gates reject all source changes. Source/correction changes advance case/source digest and invalidate unsealed approval; worker currentness checks remain authoritative. No mutation of independent target history.

Information requests are local case facts (not messages sent externally), with reason, requested fields and versions. Supporting uploads append immutable sources to the selected case through the existing sandbox intake command with case If-Match. Exact duplicate attachments are no-ops; all old sources/proposals remain. Corrections clear resolved missing/conflict flags but never relabel human assertions as extraction. Receipt arithmetic is always rederived from parsed rows, not a corrected aggregate. Partial/no-change decisions require no unresolved flags and consistent operands. Hold/escalate remain available while unresolved.

## Independent review corrections (RV-01 / RV-02 / RV-03)

- **RV-01:** all supported receipt rows must have one exact PO line ID. If invoice or purchase-order sources explicitly label `Line <token>`, their declared line IDs must equal that single receipt line. Different receipt line IDs or a mismatched declaration fail closed before proposal creation; no per-line accounting policy is added. The two-row quantity=1, price=0.05, tax=0.08 counterexample is rejected, not recalculated. Preparation reparses receipt support from immutable source text, so an older cached manifest cannot bypass this rule.
- **RV-02 final boundary cycle:** CSV/XLSX identity comes from the entire authoritative logical cell, grouped by sheet/row/column, not page projection. Supported receipt layouts use labelled rows (Receipt/Goods receipt, Line, Received quantity, Unit, Currency, Purchase order), labels in column 1 and identity values alone in column 2. Extra identity columns (including blank CSV columns), unlabelled continuation rows, duplicate identity labels, blank values, formulas, missing cell boundaries and unsupported layouts reject explicitly without a prefix row. XLSX absent empty cells follow the parser's sparse representation; present cells outside identity column 2 reject. Exact case/spelling is preserved; IDs are 1–128 ASCII `[A-Za-z0-9_-]` characters, validated with fullmatch, never stripped, normalized or sliced. 128 covers UUIDs and common external business keys while bounding persisted keys/evidence; 129 and 10000 reject, including embedded spaces/tabs/newlines and the exact reviewer values `GR_A\n/B`, `GR_A\n/C`, `1\n/2`. Numeric integral XLSX values use their complete parser logical value, not Excel display formatting. The existing single-source absent-Line default `1` remains; explicit blank Line is invalid, and multiple receipt sources require Line.

Digital PDF identity labels and values must occupy one complete physical line reconstructed from parser character boxes: consecutive word tops within 3 PDF points, word height at most 30 points. After the first identity label only recognised complete labelled field lines are supported; unknown/continuation lines and multiple values fail closed. Header lines before that region are not identity. Missing geometry is unsupported; OCR/mixed identity authority is explicitly unsupported (no OCR/model execution or OCR-accuracy claim). Non-PDF legacy literal text requires actual newline boundaries. Quantity evidence offsets remain in immutable projected text; only identity authority changed. RV-01 cross-line checks, RV-03 requests, UUID/approval gates and protected history are unchanged.
- **RV-03:** request creation requires every requested field to be currently missing or conflicting, enforced under the case lock after If-Match and idempotency replay. Open requests independently block partial/no-change preparation even on pre-fix cases without missing flags. Hold/escalate remain available. Existing versioned corrections/source append revalidate support and resolve requests only once all their fields are resolved; exact command replay and duplicate attachments do not create extra revisions or requests.
- **RV-S01:** new allocation manifests use `input_case_version` for the operands read before preparation. The proposal's existing `case_version` is the resulting saved case revision (input + 1). Existing historical manifest `case_version`, financial payloads, digests and attestations are not migrated or rewritten.

These are bounded fixes pending independent re-review, not new DOC-T passes or receipt allocation concurrency certification.

## Evidence boundaries

Authored synthetic PDF/CSV/XLSX bytes are genuine parser inputs, not private business data or model quality evidence. Isolated PostgreSQL and separate target processes are required for integration; proof ports only. Live parent supervisor/accounts remain untouched. No DOC-T ID is promoted to full pass by this finite slice; model quality remains unpassed/resource-blocked. Tests must retain RED/GREEN and real target readback evidence.
