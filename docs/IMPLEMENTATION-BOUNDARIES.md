# Implemented subset and contract deviations

> **Current implementation boundary is [CURRENT-0.2.md](CURRENT-0.2.md) and `acceptance-status.json`.** Real model-driven proposal preparation, container OCR/CSV/XLSX, nonowner forced RLS/private signed workload authority, fenced precommit recovery, durable SSE and original-byte retention have since been implemented/exercised. All original full release gates remain normative and incomplete. The numbered list below is the historical baseline, retained rather than silently rewritten as prior accomplishments.

The original blueprint and all 20 DOC-T IDs remain normative; no requirement has been silently deleted. See acceptance-status.json for incomplete release gates.

- PostgreSQL 16 (actually available cached image and tested), not the unverified PostgreSQL 17 candidate. Separate workbench/target databases and owners; verifier target reads use a SELECT-only account. Workbench API uses its database owner for bootstrap and operations: RLS/nonowner runtime segregation remains **unimplemented**.
- Workbench React/TypeScript retains all fourteen exact route IDs and original CSS vocabulary. An authored digital-PDF sample is the only enabled intake. Exact parser word-order text/character-box artifacts are real; the parser labels inserted spaces. Original-stream Unicode normalization mappings, raster OCR, hostile-upload sandbox, CSV/XLSX and general supplier reconciliation are **not implemented**. No untrusted upload is accepted.
- Manual review and deterministic accounting are real. There is **no model execution or pretend agent**. No application-scoped model runtime/weights/right-cleared provider/budget is configured; provider egress remains disabled. No existing unrelated subscription/secret is reused.
- Target operation digest is versioned Python sorted-key canonical JSON of target identity, revision and exact patch. Workbench proposal digest additionally binds the before snapshot, sources, preparer, operation key, reason and expiry. Cross-language canonical fixtures and signed cryptographic target grants remain gates; local grants are durable target records/JTIs behind distinct service capabilities, not cryptographic attestations.
- Jobs, accepted approval, dispatch gate, browser command replay and events use PostgreSQL transactions. Claim uses SKIP LOCKED, DB-clock lease, UUID attempt and increasing fence. Current attempt/lease/fence guards publish. Target fence guards both seal and first mutation; receipt replay precedes obsolete precondition checks. A new higher fence does not silently renew an old grant.
- Target commits exactly five fields, receipt, snapshots and revision together. Broker persists seal_pending before the external grant. Before-seal source invalidation/revocation denies dispatch; after-seal/pending edits return conflict. Unknown outcome recovery is deliberately read-only and conservative: authoritative absence does not automatically clear/reseal/retry. Full grant generations, clock/race matrix, fairness, heartbeat service, backoff and exhaustion alerting are **not complete**.
- Independent verifier imports no calculator/target implementation. It independently fetches target receipt/history/current record using read-only service scope; compares operation/digest/bound before snapshot/exact five values/protected fields/revision/history and reports current drift separately. Its HTTP target read uses the SELECT-only PostgreSQL principal. This is independently implemented code, **not an independent human/team security review**.
- Local accounts have durable server sessions, scrypt workbench password hashes, HttpOnly SameSite cookies, role/object/workspace checks and CSRF token+exact Origin on browser mutations. Development credentials are deliberately public and synthetic. Target operator console has its own session, read-only access and a fixed development-only account. No production auth/rate-limit/credential-isolation claim.
- Target UI is a separately served, authenticated read-only HTML console (not a separate React operator editing product). It can inspect real target records without the workbench. Full operator editing/history remains a gate.
- UI list intentionally shows only explicitly imported sample packets; infrastructure fault-test cases remain retained by UUID and in audit/evidence, not fabricated operational work. Browser state updates use polling, not SSE. API schemas are generated OpenAPI, but a generated TypeScript client is not implemented.
- Evidence exports are permission-checked small synchronous JSON snapshots with digests, originals excluded, not a durable multi-artifact export service. Retention, encryption, backup restoration, migrations with N/N-1 compatibility, load SLOs, automated redaction/secret/security review and clean-machine reproduction remain open.
- Approval identifiers in this subset use the proposal UUID on revocation routes; a separate approval entity/run entity and full normative command surface remain incomplete. The recovered dispatch is represented by its durable job and proposal gate; no fabricated run entity is exposed.
- Local proof guarantees apply to this controlled atomic target contract, not arbitrary external APIs. Unknown receipts never become successful based on amounts or a model narrative. Neither a finite suite nor this prototype establishes production/security/compliance readiness.
